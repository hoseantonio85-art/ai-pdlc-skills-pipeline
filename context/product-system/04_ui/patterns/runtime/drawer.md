# Drawer — runtime routing (NORM / ORM)

**Источник нормативных решений:** `../specs/drawer.md`, раздел «Актуальный нормативный слой». Старая техника и code-snippets ниже этого раздела — reference-only при противоречии.

## Decision
- Самостоятельный объект → Modal / Page; подчинённая задача → Drawer.
- `theme`: NORM (скруглён, Close внутри) / ORM (правый край, Close снаружи).
- `scope`: `viewport` (поверх всего, включая Modal) / `container` (в пределах Modal, перекрывая Header/Body/Footer).
- Размеры: S 608, M 720, L 840, XL 1184 px.
- Новая независимая связанная задача может породить второй, третий и последующий Drawer при понятной глубине и безопасном состоянии; нет жёсткого лимита в два. Каждый слой имеет overlay, Close закрывает только верхний.
- По умолчанию **Escape не закрывает Drawer**; это opt-in для конкретного сценария.
- Не навязывай Back/replace. Можно редактировать объект в том же Drawer. Не создавай новый Drawer для каждого шага формы.
- Header всегда видим; Body прокручивается; Footer закрепляется только если есть global actions.
- Не выдумывай интерфейс программного компонента, refocus policy и закрытие по scrim: сверить с подключённым target и утверждённым контрактом.

## Registry filter profile
Как правило, S/M; разделы с названием и локальным сбросом; глобальные `Сбросить` + `Применить`. Закрытие без применения не меняет выдачу, если не выбран live filtering.

## Object view profile
История, выбор связи, источник, комментарий и другие secondary tasks открываются поверх Modal/страницы, нижние состояния сохраняются.
