# Единый бизнес-контекст NORM

**Revision:** OpenSpec `[редакция исходника удалена]`, синхронизация 2026-10-14. **Обновляемый context provider**, не отдельный слой/надстройка.

## Где находится знание

- `02_services/services_map.md` и `02_services/*.md` — единая предметная модель и подробные карточки существующих бизнес-сервисов.
- `07_business_context/service_registry.yaml`, `capability_registry.yaml`, `role_registry.yaml`, `common_business_rules.md`, `glossary.md` — компактные машинно-читаемые **представления той же модели**, а не новые независимые факты.
- `source_authority.md`, `source_registry.yaml` — нормативный статус источников и их revisions.
- **Исходные OpenSpec в этот архив не включены**; при подключении они могут выступать нормативным источником, но только после проверки версии и доступности.

## Изменение сервисов

По поступлении новых/обновлённых спецификаций не создавать новую папку слоя: обновить существующий service document, service map, связанные registries/rules, source revision и запустить контекстный валидатор. Старые противоречия удалить или исправить. Навигационный registry загружается рано, детальная OpenSpec — по релевантной задаче.

## Граница истинности

Существование описанного в OpenSpec сервиса/доменного требования — **подтверждённая бизнес-модель**. Текущая включённость конкретной фичи в production, её релиз и runtime требуют отдельной технической проверки.
