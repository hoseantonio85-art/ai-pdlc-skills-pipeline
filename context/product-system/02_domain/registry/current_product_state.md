## Что известно как бизнес-истина

- Подключён 90-документный снимок OpenSpec текущих существующих сервисов, включая backend и frontend-спецификации.
- Подтверждены бизнес-объекты, доменные сценарии, часть разрешений и workflow: реестр рисков, лимиты, События, меры, AI-агенты, продукты, контрагенты, компания/тарифы/сотрудники, справочники, документы и платформенные связи.
- Компактная карта этих областей — `02_domain/registry/service_registry.yaml`; подробная — `02_domain/services/`; точные требования — оригинальные OpenSpec.

## Что отдельно не проверено

- какие из специфицированных сценариев именно сейчас включены на production и для каких tenants;
- релизы, feature flags, текущий route map, runtime API, визуал production;
- полная единая матрица прав по всем сервисам; UI-чата/мониторинга/RAG как полный набор спецификаций;
- аналитика и реальные пользовательские метрики.

## Для Intent / UX / SDD

Использовать OpenSpec как нормативное описание существующего сервиса, не создавать заново уже специфицированный workflow. Для отдельных production-проверок запрашивать task-specific evidence; не деградировать нормативный сервис до гипотезы только из-за отсутствия runtime-скриншота.
