# Текущие ограничения и границы подтверждения NORM

## C-NORM-001. Первичные спецификации подключены

На 2026-10-14 подключены 90 канонических OpenSpec существующих сервисов NORM из ревизии `[редакция исходника удалена]`. Риски, лимитная кампания, События, меры, ИИ-агенты, продукты, контрагенты, организация/тарифы/сотрудники, справочники и часть базы знаний имеют предметные требования. **Не** считать их неизвестными только по причине отсутствия прежней карточки сервиса.

## C-NORM-002. Релиз и runtime — отдельные источники

OpenSpec является истиной о нормативном поведении сервиса, но без реестра релизов и проверки runtime нельзя утверждать дату выхода, актуальный feature flag и точный production-визуал.

## C-NORM-003. Права описаны по сервисам, а не общей матрицей

В OpenSpec доступны отдельные permissions/workflow-ограничения, но полного единого каталога прав нет. Для конкретного действия читать права соответствующей OpenSpec; не угадывать матрицу по названиям ролей.

## C-NORM-004. Точная доменная модель — в OpenSpec

Поля, допустимые статусы, переходы, расчёты и обязательность для покрытых доменов брать из исходной спецификации. Не утверждать, что формальной модели вообще нет; неполнота остаётся для некоторых смежных областей.

## C-NORM-005. Не все смежные UX-сервисы исчерпывающе специфицированы

Полная пользовательская модель AI-чата, мониторинга внешних новостей и полный RAG lifecycle не покрыты предоставленным снимком. Уточнять на уровне задачи, не домысливать.

## C-NORM-006. Технические артефакты и продуктивная сборка

OpenSpec содержит описание некоторых API и интерфейсов; полный живой frontend/backend runtime, интеграционные секреты, release registry и production данные не подключены. Продуктовая модель не предписывает напрямую backend implementation.

## C-NORM-007. Метрики и аналитика

Общий продуктовый каталог метрик и достоверные runtime-показатели не подключены. Business KPI и аналитические UI-примеры не объявлять фактическими цифрами.

## C-NORM-008. Лимитная кампания уже подтверждена как сервисная область

`LIMIT_CAMPAIGN`, `LIMIT_ENTITY` и `LIMIT_INFO` описаны в `limit-management/spec.md`; нельзя относить их к гипотезам. «Объект оценки» существует как концепт в доменных моделях; отдельный пользовательский сервис с таким названием не подтверждён.

## C-NORM-009. Продуктовая стадия не загружает фронтенд по умолчанию

UX/UI Kit и инженерные правила остаются в своих stage-профилях. Это не влияет на авторитетность OpenSpec по бизнес-логике.

## C-NORM-010. Ответственный за актуализацию

Правка будущей версии бизнес-спецификации должна обновлять единый набор service documents/registries и source revision. Ответственный поимённо не назначен; в инкременте фиксировать источник и дату синхронизации.
