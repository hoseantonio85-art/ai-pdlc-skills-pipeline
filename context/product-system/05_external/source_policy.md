# Внешние источники — источники отдельно, конфигурация через YAML

Это **публичный шаблон**. Реальные внутренние спецификации, UI Kit и код в поставку не входят.

## Порядок подключения

1. Выбери контекст через `<project>/.gigacode/product-context.yaml` и `~/.gigacode/product-contexts.yaml`.
2. Для внешних спецификаций, UI Kit и репозиториев прочитай `~/.gigacode/product-evidence.yaml`. Шаблон — `agent/.gigacode/product-evidence.yaml.example`.
3. Можно указать **абсолютный локальный путь** или **URL**. URL сам по себе не означает, что файл доступен: открывай только с доступными инструментами и полномочиями. Не сохраняй приватные токены в публичном YAML.
4. Проверяй физическую доступность, версию и дату. Читай только источники задачи.
5. Если источник не доступен — `NEEDS_SOURCE` или `BLOCKED_BY_SOURCE`, без выдуманных бизнес-фактов, полей, сценариев и API.

Сохраняй реальные персональные пути, адреса, домены и ключи **только на личной машине**, не коммить их в репозиторий. Для работы с конфиденциальными источниками соблюдай внутреннюю политику доступа и обработки данных.
